## Low
- [R1-L1][Low][OrphanedRunRecovery.php・Core/Plugin.php・docs/03・docs/10] 「既定の設定では致命的エラーのフックが走らない」は WP-CLI に限った事実。WordPress の致命的エラーハンドラーは `'exit' => false` で `wp_die()` を呼び、Web のリクエストの既定のハンドラーは終了しない。走らなかったのは WP-CLI の `wp_die` のハンドラーが終了するため → **修正済み**（記述を直し、Web のリクエストの中で AS のキューランナーを動かす一時の mu-plugin で、フックがその場で `fatal_error` にすることを実測。dev サイトの WP-Cron は止まっていて `wp-cron.php` では測れなかった）
- [R1-L2][Low][OrphanedRunRecovery.php:fatal_error_message()] 外すのが ABSPATH だけで、ABSPATH の外の `WP_CONTENT_DIR`（Bedrock 等）のサーバーの絶対パスが画面に残る → **修正済み**（`WP_CONTENT_DIR` を `wp-content/` に、ABSPATH とその親を空に。`wp_normalize_path()` で区切りをそろえる。テストを追加。親の除去を外す変異は落ちる。`WP_CONTENT_DIR` の置換を外す変異は、テスト環境の `WP_CONTENT_DIR` が ABSPATH の中にあって結果が変わらないので検出できない〔定数を差し替えられない環境の制約〕）
- [R1-L3][Low][RestController.php:list_runs()] 回復と一覧がそれぞれ `find_active_runs_for_platform()` を走らせ、照会が倍になる → **修正済み**（`OrphanedRunRecovery::recover_and_list()`。何も失敗にしなければ判定に読んだ一覧を返す。失敗にしたのに古い一覧を返す変異は `RestControllerRecoveryTest` が落ちる）。古い run に pending のアクションがある間は照会のたびに AS を読む点は残る（docs/03 §5 に記録）
- [R1-L4][Low][JobRepositoryTest::test_live_action_job_ids_lists_the_jobs_with_pending_or_in_progress_actions] `set_up` の取消しは pending だけなので、tests サイトにコミット済みの in-progress のアクションがあると余分な ID が混ざって落ちる → **修正済み**（このテストのジョブとの共通部分で比べる）
