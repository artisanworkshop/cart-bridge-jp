## 指摘
### [R1-1][Medium][includes/Woo/Writer/OrderWriter.php（新規作成の1回だけの保存）]
即時取込みモード（`woocommerce_analytics_scheduled_import` が `yes` でない。WooCommerce 10.5 より前から使っている店舗の既定）の Analytics は `woocommerce_update_order`・チェックアウト専用の `woocommerce_create_order`・`woocommerce_schedule_import` でしか取込みを予約しない（`OrdersScheduler::init()`、実ソースで確認）。以前は `wc_create_order()` の後の2回目の保存（更新）が予約していたが、1回だけの保存では予約されず、移行した受注が売上レポートから黙って抜ける（独立レビュー R1-S1）。
**修正方針:** 新規作成の保存に成功したら `do_action( 'woocommerce_schedule_import', $order_id )`。→ 修正済み（`17d3069`。テスト＋ミューテーション CAUGHT）

### [R1-2][Medium][includes/Woo/Writer/OrderWriter.php（`wc_paying_customer()`）]
`wc_paying_customer()` が try の外にあり、顧客の保存で他プラグインが失敗すると、受注は作成済みのまま例外が `write()` の外へ出る。Importer は mapping を書かず無料枠も返すため、次回に同じ受注を重複作成し、上限にも数えられない（独立レビュー R1-S2）。
**修正方針:** 作成後の後処理（Analytics の予約・購入実績）を `after_creating()` にまとめ、失敗は受注を消さず WooCommerce のログに残す。→ 修正済み（`17d3069`。テスト＋ミューテーション CAUGHT）

## 確認して問題なしとしたもの（独立レビュー）
- `set_status()` の変化前は view 文脈の `get_status()`（`woocommerce_default_order_status`）で、`from === to` なら記録しない（実ソース・使い捨て受注で実測）
- フィルターは `finally` で外れ、`set_prop()` はフックを持たないので再入の余地なし。on-hold／`checkout-draft` へのフォールバック・stale ID・`validate()` も同じ経路

- 件数キャッシュのテストは `refresh_cache()` で温めており、旧フローのずれを検出できる。フックはテストフレームワークが戻すので順序依存なし
