## 新規指摘（R1 の修正で混入したもの）
### [R2-1][Low][includes/Woo/Writer/OrderWriter.php（ID 0 の見送り）]
ID 0 を例外ではなく `ORDER_CREATE_FAILED` で返すため、Importer の catch を通らず `cbjp_logs` に remote_id 付きの記録が残らない。本番の実行は項目ごとの警告を保存しない（R3-0k で v1.0 対象外と決定済み）ので、どの受注を作れなかったかは WooCommerce のログ（「(no ID)」）の日時から追うしかない。再試行の扱いは例外のときと同じで、他の writer の `*_SAVE_FAILED` とも揃っている。
**対応:** 診断のしにくさだけなので、`docs/03` に追い方を明記

### [R2-2][Low][includes/Woo/Writer/OrderWriter.php:after_creating]
後処理の失敗は WooCommerce のログにしか出ず、mapping と checksum は保存されるため再試行されない（結果レポートも普通の作成に見える）。設計どおりの割り切り。
**対応:** `docs/03` に明記（Analytics は「Import historical data」で取り戻せる）

## 確認して問題なしとしたもの（独立レビュー）
- 早期 return で落ちる `$prepared->warnings` は本番の件数集計に影響しない（`ORDER_CREATE_FAILED` で warned +1）。dry-run は `validate()` なので無関係
- `save()` が 0 を返したのに行が残るケース: HPOS はプレースホルダー投稿の作成直後に ID を設定するため、以降の失敗は 0 以外になり R1-X1 の範囲。`wp_insert_post()` 内のフックの例外で残りうるプレースホルダー投稿は修正前（6fbb295）からある
- クロージャーは static で `use` は値渡し、手順の順序依存なし。ログの context に個人情報なし
- 新しいテスト 4 件は単独実行でも通り（順序非依存）、ミューテーションで落ちる（トートロジーでない）
