## 指摘
### [R1-1][Medium][tests/unit/Adapters/ColorMe/ColorMeAdapterTest.php]（独立レビュー S-1）
`test_push_product_omits_both_variant_prices_when_the_sale_price_cannot_be_converted` は `tax_type=excluded`（税率欠損）で通常価格も換算不能になるため、「実売価格だけが換算できない」分岐（`$sale===null && $regular!==null`）を通らず、分岐を壊しても通るトートロジーだった。
**対応:** `tax_type=included`＋`sale_price='abc'` で通常価格を `option_price` に送らないことを検証するテストに差し替え、税設定不能のテストは別名で残した（07c3931）。**解消**

### [R1-2][Medium][ProductReader.php / ColorMeAdapter.php]（独立レビュー S-2、要判断）
セール終了日（`date_on_sale_to`）を運べないまま、期間限定セールの実売価格を ColorMe の恒久的な販売価格として送る（Woo 側でセールが終わっても ColorMe は値引き価格のまま。金銭的リスク＝売価が低すぎる方向）。単純商品の `push_prices()` にも既にある構図（本 PR 以前から。backlog 未記録）だが、バリエーションでは本 PR で新たに送るようになった。
**裏取り:** `includes/` に `date_on_sale` 処理が 0 件（grep）。`is_on_sale('edit')` は終了日が未来なら真。
**対応:** 単純商品・バリエーションとも、終了日付きのセールを送るときは情報警告 `SALE_END_DATE_NOT_PUSHED`（バリエーションは `:{id}`、非 blocking）を積む。blocking にすると期間限定セール中の商品を一切エクスポートできないため見送り（設計判断として `docs/03` §10.2 に記録）。テスト追加（07c3931）。**解消**
