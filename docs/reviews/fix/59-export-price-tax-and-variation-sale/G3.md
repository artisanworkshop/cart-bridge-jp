## 指摘
### [G3-1][Copilot][Medium→Low][includes/Adapters/ColorMe/ColorMeAdapter.php:1095]
`CanonicalProduct::$variants` は外部アダプタ境界のため `sale_price` が `ProductReader::valid_sale_price()` を通っている保証が無い。`'0'`/`'-10'` は `to_push_amount()` の `included` 経路でそのまま 0/-10 になり、`option_price` として送られてバリエーションが無料・不正な価格になりうる。換算後の販売価格が正で、有効な通常価格未満であることを検証し、通常価格が使えない場合は価格フィールドを両方省くべき。
判定: **修正**。実測（`tax_type=included`）で `to_push_amount()` が `'0'→0`・`'-10'→-10`・`'2500'→2500` をそのまま通すことを確認。`ProductReader` は上流で検証するため通常経路では到達しないが、CLAUDE.md 原則 8/9（外部境界の Canonical を信用せず、金銭的リスクは安全側）に照らして、新規コードの防御漏れ。`push_variant_details()` で「換算後の販売価格が非 null・通常価格も換算可能・販売価格が 0 超・通常価格以下」のときだけ `option_price`（販売価格）・`option_market_price`（定価）を送り、それ以外は両方省く（ColorMe 側の既存値を保持。`null` 明示は採らない: G2-1 参照）。通常価格と販売価格が換算の丸めで等しくなる境界は許容。既存の通常価格経路（`variant['price']` のまま送る）は本 PR 以前からの挙動で、`Reader` が 0 円を正規の無料商品として許容するため触らない。
**対応:** データプロバイダ付きテスト（0 / 負値 / 定価超え）と同額許容のテストを追加、docs/03 §10.2 に追記 / スレッド: https://github.com/artisanworkshop/cart-bridge-jp/pull/61#discussion_r4090024208
