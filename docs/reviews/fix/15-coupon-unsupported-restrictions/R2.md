## R1-1 の取り消し（重要）
R1 のサブエージェント指摘「制限フェイルクローズの警告に detail が無いと、店舗オーナーは
『取り込まれなかった』のか『制限が落ちたまま有効なクーポンが Woo に残っている』のかを区別できない」は
**前提が成立していなかった**。R2 の検証で次が判明したため、detail を載せる変更を取り消した:

- dry-run レポートは行ごとに `existing_local_id` 列を持つ（`Admin\DryRunReportCsv::HEADER`、
  `Sync\Importer::process_items()` が同じ変数を渡している）。警告コードと同じ行に既に載っているため、
  detail は同じ値の重複でしかない
- 実移行（非 dry-run）では `Importer::process_items()` が per-item の警告をそもそも永続化しない
  （`Importer.php:425-438` の `$is_dry_run` ガード。`DryRunItemRepository::insert_many()` の呼び出しは
  この 1 箇所のみ）。したがって detail は本移行のレポートには一切現れない
- `COUPON_CODE_CONFLICT` の detail は「衝突した**別**クーポンの ID」＝行に無い情報を運ぶため非対称であり、
  同じ形式を踏襲する理由にならない
- 派生して、R2 の新規指摘 2 件（mappings 由来の stale ID が detail に載って偽陽性になる /
  `COUPON_RESTRICTIONS_UNKNOWN` の docblock が参照先の断定的な説明文まで引き継ぐ）も同時に消滅した

R1-2（更新パスの回帰テスト）は detail と独立に有効なため維持し、アサーションを素の警告コード比較に戻した。
