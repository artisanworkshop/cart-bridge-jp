## 指摘
なし（Critical / High / Medium）。

独立サブエージェントが確認して問題なしとした主な点:
- 重複作成の穴: 作成経路で remote_id が確定した後の処理はすべて `finish_product_push()` に入る（2回目の `to_create_payload()`・`requires_hidden_safeguard()`・`can_push_images()`・`wp_remote_get()` を含む）。`catch` の外に残るのは `Cast` とログだけ。POST 応答に id が無い経路は D21-B（#73）の対象で backlog にも明記済み。`push_customer`/`push_order` は作成後にリクエストが無く、`push_coupon` は未対応で、同じ穴は無い
- `Exporter` の2重 try: 内側から投げ直した例外は外側のレート制限 catch と汎用 catch に届く。`PartialPushException` は必ず `$did_push` が true になる。バリエーションは `variant_remote_ids=[]` で checksum=null になり variant mapping は書かない。再スローは upsert の後（ループ本体の末尾）
- 再開後: 更新 payload に `category_id_small`/`group_ids`/`stocks` が入るので追いPUT で反映するはずだった項目が補われる。`sync_variants` は `ensure_option_values` で足りない値だけを追加するのでオプションは二重に作られない
- テストの質: data provider の5シナリオは別々のリクエストだけが例外を投げ、needle が部分一致で衝突しない。`assertSame( $cause, getPrevious() )` で狙った分岐に到達したことを担保している。モックへの `throw` 追加で既存 107 件は全て通る

## 対象外指摘（差分範囲外）
- [R1-X1][Medium] hidden 安全策が更新経路には効かない（`ProductTransformer::to_create_payload`/`to_update_payload`、`ColorMeAdapter::push_product`）。**裏取り済み**: 更新 payload は `base_payload()` の `display_state`（Woo の status どおり `showing`）をそのまま送り、価格／税区分を換算できないときはそれらを省く。作成のみに限定したのは R2 指摘による既知の設計で、`test_push_product_does_not_force_hidden_on_update_when_price_cannot_be_resolved` が固定している。安全策付きで作成された商品は checksum=null のままなので、次回の更新 PUT で価格が未設定／税区分が誤ったまま公開されうる。R3-0a の「作成後に中断→約60秒後に再開」でも同じ経路を通るが、中断が無くても次回 export で同じで、差分起点より前からある挙動（従来は重複作成に隠れていた）。設計判断が要るため backlog へ（起票はユーザー判断）
