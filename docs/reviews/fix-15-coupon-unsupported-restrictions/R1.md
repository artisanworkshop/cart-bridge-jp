## 指摘
### [R1-1][Medium][includes/Woo/Writer/CouponWriter.php:77-87]
フェイルクローズが「新規作成の抑止」しか行わず、既に取り込み済みのクーポン（`$existing_local_id` 非 null）には
効かない。ASP 側で後から制限が付いた場合、Woo 側の実体は「制限が落ちたまま有効なクーポン」として残り続けるが、
警告に detail が無いため、店舗オーナーはレポートから「取り込まれなかった」のか「危険なクーポンが生きている」のかを
区別できない。
**修正:** `$existing_local_id` が非 null のとき `WarningCode::with_detail( ..., (string) $existing_local_id )` で
既存 ID を detail に載せた（`COUPON_CODE_CONFLICT` と同じ形式）。アーキテクチャ原則 4 により Woo 側の実体は
削除も無効化もしない方針は維持。

### [R1-2][Medium][tests/unit/Woo/Writer/CouponWriterTest.php]
制限フェイルクローズのテストが全て `$existing_local_id = null`（新規作成パス）のみ。同ファイルにはコード衝突には
更新パス専用の回帰テストがあるのに、制限側には無い。判定が `new WC_Coupon( $existing_local_id )` + `set_*` より
後ろへ移動しても全テスト green のまま既存クーポンを書き換え始める。
**修正:** `test_restricted_coupon_does_not_overwrite_an_already_imported_coupon`（dataProvider で `true` / 未宣言の
2 ケース）を追加。skipped であること、detail に既存 ID が載ること、既存クーポンの `amount`/`code` が不変であることを検証。

### [R1-3][Low→修正][includes/Canonical/CanonicalCoupon.php / includes/Woo/Writer/CouponWriter.php / includes/Woo/WarningCode.php]
新設 docblock が「特定の商品グループ・会員グループ限定といった利用制限は Woo のネイティブなクーポン設定では
表現できない」と書いていたが事実誤り。WooCommerce は `set_product_ids()` / `set_product_categories()` /
`set_excluded_product_categories()` / `set_email_restrictions()` をネイティブに持つ（wp-env 実測: WC の
`class-wc-coupon.php` 706/772/783/831 行）。実際の除外理由は「ColorMe のグループ→商品 ID 集合を変換層で展開
できない」こと。新アダプタの作者がこの記述を読むと、Woo で表現可能な制限にまで `true` を立ててクーポンを
不要に全滅させかねない。
**修正:** 「Woo で表現できない」→「Woo のクーポン設定へ写せない」に言い換え、Woo 側が持つ制限軸を明示した。
backlog ではなく本ラウンドで修正した理由: 本 PR で新設した公開契約の docblock そのものの事実誤りであり、
同じ差分内で直す方が安いため。

### [R1-4][Low→修正][docs/10-tasks.md]
checksum 変化の影響を「1 度だけ再書き込みされる（冪等な update）」とだけ書いていたが、再書き込みは ASP 側に
変更が無くても全既取込みクーポンに発生し、`prepare()` が金額・期限・説明等を一括で set し直すため、移行後に
店舗が Woo 側で手直しした内容が 1 度だけ巻き戻る。初回 dry-run では差分ゼロでも全件 `updated` と並ぶ。
**修正:** 上記を追記。あわせて「checksum 安定のため新フィールドを `to_array()` から外す案は、`false`→`true` の
反転を checksum 一致スキップが握り潰すため採らない」ことも明記（再検討の手戻り防止）。

### [R1-5][Low→修正][tests/unit/Adapters/ColorMe/Transform/CouponTransformerTest.php:104-110]
`transform()` の戻り値を null チェックせずプロパティ参照していた（同ファイルの他テストは `assertNotNull` を挟む）。
PHPStan は `paths: includes` のみで tests/ を解析しないため静的にも捕まらない。
**修正:** `assertNotNull()` を追加。

### [R1-6][Low→修正][tests/unit/Canonical/CanonicalModelRoundTripTest.php]
三値のうち往復が検証されていたのは `false`（provider）と「キー欠損→null」のみ。`true` と「明示的な `null`」の
往復が未検証で、`isset()` 判定により明示 null とキー欠損が同一視されることも固定されていなかった。
**修正:** dataProvider 化して 4 ケース（キー欠損 / 明示 null / false / true）を `from_array()`→`to_array()` で往復検証。
