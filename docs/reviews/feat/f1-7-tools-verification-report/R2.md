## 新規指摘（R1 修正で混入したもののみ。Critical/High なし）
### [R2-1][Low][includes/Woo/Tools/SampleCleanup.php:run_batch] variant エンティティの行で予算を 2 消費していた
`++$deleted[$entity]` が予算計算より先に走るため、`variant` の mapping 行を削除したとき `$deleted['variant'] - $variants_before` が 1 になり `1 + 1` 引かれていた（データ破壊なし。バッチ回数が倍になるだけ）。
**対応:** `remove_entity()` 直後に cascaded 件数を確定させてから減算するよう修正（本ラウンドで修正）。

### [R2-2][Low][includes/Woo/Tools/SampleCleanup.php:deletable_attachment_ids] 複数商品が共有する画像は生存商品からの参照を追跡しない
`MediaImporter` は同一 `_cbjp_source_url` の添付を商品をまたいで再利用するため、`post_parent`（最初に取り込んだ商品）が消えると、別の生存商品（mapping 消失・複製等）がギャラリー等で参照していても孤児と判定される。R1 前は全所有添付を無条件削除していたので回帰ではなく残課題。
**対応:** backlog（`_thumbnail_id`/`_product_image_gallery` の参照確認を追加する改善余地）。クラス docblock の記述を実態に合わせて修正。

### [R2-3][Low][includes/Woo/Tools/SampleCleanup.php:deletable_attachment_ids] 添付候補を毎バッチ全件取得する（O(N²/budget)）
候補に上限を付けると「削除できない候補」が窓を埋めて進まなくなるため全件判定にしているが、画像の多い Pro 店舗ではバッチ毎の読込が重い。
**対応:** backlog（`post_parent__in` 等で候補を絞る改善余地）。

### [R2-4][Low][includes/Admin/RestController.php:platform_param] docblock が `run_id_param()` 側に付け替わっていた
**対応:** 元の docblock を `platform_param()` の直上に戻した（本ラウンドで修正）。

### [R2-5][Low][tests/unit/Woo/Tools/SampleCleanupTest.php:test_staff_accounts_and_the_current_user_are_never_deleted] R1-4 の追加で空振りになっていた
実行者が customer のため capability 不足だけで unlink になり、保護ロール・自分自身のガードを検証しなくなっていた。
**対応:** 実行者に `delete_users` を付与し、自分自身に対する `delete_user` が開いていることを確認したうえでガードだけで unlink になることを検証（本ラウンドで修正。管理者を対象にした `delete_user` は WooCommerce の `wc_modify_map_meta_cap` が非管理者に対して拒否するため、その前提も併記）。
