## 指摘
### [R1-1][Medium][plugins/cart-bridge-jp/includes/Entities/EntityTypeRegistry.php:warning_flags]
警告の印の索引 `$flag_index` は `plugins_loaded` の途中でもキャッシュされる（種類の一覧は途中ならキャッシュしない）。途中で判定が走った後に種類が登録されると、`reset_cache()` まで受注の blocking の印（`ORDER_TOTALS_INVALID` 等）が無いままになり、エクスポートが止まらない（fail-open。サブエージェントが実測）。
**修正方針:** 索引も種類の一覧と同じ条件（`plugins_loaded` の後）のときだけ保持する。

### [R1-2][Medium][plugins/cart-bridge-jp/includes/Entities/EntityTypeRegistry.php:link_sources/mapping_kinds]
LinkSource・MappingKind のキーは無料版のものを守っておらず（position の小さい外部の種類が `category` を先に取ると、無料版のものが「already registered」で外れる）、LinkSource のキーの形も検証していない（20 文字を超えるキーが `cbjp_mappings.entity_type` で黙って切り詰められる）。実測でリンク再構築が post_tag の ID を `category` の mapping に書いた。
**修正方針:** 無料版の種類の LinkSource・MappingKind を先に確定させて外部の同じキーを拒否し、LinkSource のキーにも種類のキーと同じ形（`^[a-z][a-z0-9_]{0,19}$`）を求める。

### [R1-3][Medium][plugins/cart-bridge-jp/includes/Admin/RestController.php:entity_options]
`is_export_beta()` が例外を投げると `safely()` が false を返し、`beta:false`（＝既定で選ぶ）になる。D24 のベータは「既定で選ばない」ための印なので fail-open（原則 9）。
**修正方針:** ベータの判定は例外のとき true（ベータ扱い）に倒す。

### [R1-4][Medium][plugins/cart-bridge-jp/includes/Sync/Importer.php・Exporter.php（remote_amount・dry_run_label）]
外部の種類の `remote_amount()`・`dry_run_label()` をアイテムごとの try の外（一部は VALIDATION_EXCEPTION の catch の中）で呼ぶ。1 件で例外が出ると `run_page()` ごと落ち、catch の中では元の例外も消える（「1 件の異常データで移行全体を止めない」に反する。実測）。
**修正方針:** 2 つの呼び出しを Throwable で受けて null・空文字に倒し、例外クラスを記録する。

### [R1-5][Medium][plugins/cart-bridge-jp/includes/Sync/JobManager.php:start_run_locked]
以前はアダプタの `capabilities()` が例外を投げると `start_run()` が失敗していたが、`safely()` が無料版の種類の判定でも例外を握るため、要求した実体（顧客など）が黙って外れて run が始まる（異常系の振る舞いの変化。backlog `r3-0j-premium-beta-features/R1-X1` と同じ経路）。
**修正方針:** 絞り込みの前に `$adapter->capabilities()` を 1 回 `safely()` の外で呼び、アダプタの失敗は従来どおり外へ出す。

### [R1-6][Medium][plugins/cart-bridge-jp/tests/unit/Entities/DispatchCharacterizationTest.php（不足）]
種類へ移した判定のうち `records_push_intent()`（旧 `Exporter::PUSH_INTENT_ENTITIES`）と受注の `is_export_beta()` を固定するテストが無い（どちらも変異を入れても全件が通った。実測）。
**修正方針:** 種類ごとの `records_push_intent()` の表と、`BETA_ORDER_EXPORT` を宣言したアダプタでの `GET /connections` の `beta` を特性テストに足す。

### [R1-7][Medium][plugins/cart-bridge-jp/includes/Woo/WooRepositoryFactory.php・WooReaderRepositoryFactory.php]
外部の `writer()`・`reader()` の例外を記録せずに捨てる。アイテムは `ENTITY_NOT_SUPPORTED`、Reader 側は「No Woo reader registered」になり、本当の原因が見えない（エラーハンドリング不足。サブエージェントは Low としたが、原因の記録が無いことは Medium の定義に当たる）。
**修正方針:** 例外クラスを `Logger` に記録する（個人情報を含めない）。
