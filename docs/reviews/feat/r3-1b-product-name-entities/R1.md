## 指摘
### [R1-1][Medium][includes/Woo/Support/HtmlText.php:from_plain]
制御文字（タブ・改行・復帰を除く `\x00-\x1F`）を残すので、kses の `wp_kses_no_null()` が WP-Cron でだけ消し、管理者では残る（`"A\x0BB"` が cron で `AB`、admin で `A\x0BB`。独立レビュー A-1 が実 Writer で実測）。実体参照にしても kses が `&amp;#11;` に書き換える。
**修正方針:** `from_plain()` の先頭で同じ範囲を除く。`HtmlTextTest`・`ProductWriterTest`（両ランナー）にケースを足す。
**修正:** 対応済み。`mutate-check.sh` で除去の行を消すと 2 件（`HtmlTextTest`・`ProductWriterTest`）が落ちる（`--only` で CAUGHT。失敗の出力に制御文字が混ざって照合できないので、テストコマンドの出力から制御文字を除いて照合した）。

### [R1-2][Medium][tests/unit/Woo/Writer/ProductWriterTest.php:test_updating_under_the_other_runner_keeps_the_name]
WooCommerce は投稿の列（名前・説明・状態など）が変わったときだけ `wp_update_post()` を呼ぶ（`WC_Product_Data_Store_CPT::update()`）。2 回目の write が価格しか変えないので名前が kses を通らず、「更新時だけ符号化しない」退行でも通っていた（独立レビュー A-2）。
**修正方針:** 2 回目の write で短い説明も変え、`post_updated` の発火と `post_excerpt` の更新を前提として assert する。
**修正:** 対応済み。`mutate-check.sh` で「作成時だけ符号化」に変えると、このテストだけが落ちる（`--only` で CAUGHT）。
