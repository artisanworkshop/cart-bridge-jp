## 独立サブエージェントレビュー（`general-purpose`、opus。`main...bad9060`が対象）

### [R1-1][Medium][src/tabs/ExportTab.tsx:953-960 / 541-595]
`acknowledgeProductionWrite`はプラットフォーム切替時にしかリセットされず、実exportの開始・
完了でも false に戻らない。チェック後は同一画面のまま2回目以降の本番exportがボタン1クリックで
始まり、`ImportTab.tsx`の`window.confirm()`（クリック毎に確認）よりD17の確認の強さが落ちる。
**判定:** 妥当。実exportのPOST成功時に`setAcknowledgeProductionWrite(false)`を追加。
**対応:** `52d35a0`

### [R1-2][Medium][src/tabs/ExportTab.tsx:144-153]
`zeroWrittenWarnedEntities()`の`warned>0`条件は、checksum一致でskipした場合でも
`Sync\Exporter::process_items()`が読出時点の非ブロッキング警告を`warned`へ加算し続ける
（`Exporter.php`162-164行）ため、健全な冪等再exportでも誤ってバナーが出うる。
**判定:** 妥当（コード読解で確認済み）。条件を`warned===processed`（処理した全件が警告）へ
絞り、偽陽性を大幅に減らした（完全な排除ではないが、原型のbacklog `e2-2-exporter-core/R1-M8`
が想定する「実質何も進まなかった」ケースに近い判定になる）。
**対応:** `52d35a0`

### [R1-3][Medium][src/tabs/ExportTab.tsx:597-651]
新設の`retryExportJob`/`cancelExportRun`は`startExportRun`・limits取得effectと異なり
`platformGenerationRef`による世代判定を持たず、ファイル冒頭のコメントが「全ての非同期処理で
共有する」と宣言している設計と食い違う。v1.0はプラットフォームセレクタ自体が出ないため実害は
無いが、修正コストが低く整合性の価値が高いため対応。
**判定:** 妥当。両関数に世代ガードを追加。
**対応:** `52d35a0`
