### [G3-3][Codex][Medium（P2）][src/tabs/ExportTab.tsx:483]
実exportの`/limits`取得effectが`platformGenerationRef`のみで古い応答を判定しており、同一
プラットフォーム内で新しいrunが始まった場合（run A完了時の`/limits`取得中にrun Bを開始）は
検知できない。run Aの応答が遅れて届くと、run B開始時に`setLimits(null)`でクリアした`limits`を
run Aの古い使用状況で上書きしうる（`LimitsUpsellNotice`の表示が古くなる。データ破壊は伴わない）。
判定: 妥当。フロントエンドのみで修正可能なため対応。
**対応:** `f3e1cb7`（`useRunPolling`の`runIdRef`と同じ考え方で`exportRunIdRef`を追加し、
limits取得時に捕捉した`run_id`と応答受信時点の値が一致するかも確認するよう修正。実機で
LimitsUpsellNoticeが引き続き正常表示されることを確認）。/ スレッド:
https://github.com/artisanworkshop/cart-bridge-jp/pull/53#discussion_r4080696929（Resolve済み）
