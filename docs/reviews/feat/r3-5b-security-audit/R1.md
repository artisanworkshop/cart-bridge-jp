## 指摘
### [R1-1][Medium][plugins/cart-bridge-jp-pro/includes/Woo/Writer/CustomerWriter.php:83, 199（resolve_target）]
メールの一致で見つけたアカウントに `resolve_target()` が必ず `customer_reused_existing` を付け、`write()`・`validate()` が無条件に積むため、取込みがこの顧客のために作ったアカウント（mapping を失った後にメールで見つけ直した）を更新したときも「この顧客のために作ったのではない…変更しない」と報告する。保護したアカウントでも「注文をそのアカウントに割り当てる」と `customer_account_protected`（ゲスト）が同じ行に並ぶ。
**修正方針:** 理由は紐づけだけの経路（`link_only()`・`validate()` の同じ分岐）でだけ積む。`CustomerResolution` から `reuse_warning` を外す。→ **修正済み**（c68a9a3。テスト `test_own_account_found_again_by_email_is_updated_without_the_link_only_reason`・`test_protected_account_is_not_reported_as_linked`）

### [R1-2][Medium][plugins/cart-bridge-jp/tests/unit/Woo/Support/ProductResolverTest.php / SkuGuard.php]
`test_a_model_number_that_cleans_to_nothing_finds_nothing` はトートロジー（テストの DB に SKU が空の商品が無いので、空の SKU で引く変異でも通る）。WooCommerce は空の SKU でも照合するので、SKU の無い自前の商品（重複で SKU を空にした商品・`<b></b>` の型番）に受注の明細・在庫が結び付きうる。
**修正方針:** SKU が空の商品を作ってから空・空白・タグだけの型番が何も引かないことを確かめる。→ **修正済み**（b43287e。R1-L5 と合わせて `SkuGuard::lookup_key()` にした。変異 `normalize-empty`・`lookup-unchanged` が検出）
