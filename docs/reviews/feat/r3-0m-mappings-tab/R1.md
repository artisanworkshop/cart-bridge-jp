## 指摘

### [R1-1][Medium][src/components/OrderMappingNotice.tsx・src/tabs/MappingsTab.tsx／includes/Woo/WarningCode.php:indicates_unresolved_reference()]（独立レビュー S-1・S-X1）
マッピング未設定のまま本取込みした受注は、ほかの参照が解決済み（ゲスト受注など）なら `OrderWriter` が `fully_resolved=true` を返し、`Importer` が checksum を保存する。
後から Mappings タブで設定しても、再 dry-run は checksum 一致の経路で `validate()` を呼ばずに警告なしの行を書くので警告だけが消え、本取込みも飛ばされて受注は空の決済方法のまま残る。
新しい案内文も Mappings タブの説明もこの点に触れておらず、新テストのコメント「マッピング変更後の dry-run で確かめる設計のまま」は実際の挙動と違っていた。
**裏取り:** `OrderWriter.php:126`（`! indicates_unresolved_reference()`）、`Importer.php:290-310`（checksum 一致で `warnings => []` の skipped 行）、`Importer.php:392`（`fully_resolved` のときだけ checksum）を読んで確認。更新経路の `prepare()` は決済方法と配送行を毎回付け直す。
**対応: 修正済み**（根本対応。承認済み計画の「checksum は不変」からの変更として**ユーザーに確認して承認を得た**）:
- `PAYMENT_METHOD_UNMAPPED`/`SHIPPING_METHOD_UNMAPPED` を `indicates_unresolved_reference()` に加え、未マッピングの受注は checksum を保存しない（`0bbcc57`）。エクスポートは未マッピングの受注を送らず（`ColorMeAdapter::order_skip_warnings()`）checksum も保存しないため影響しない。代償は、未マッピングのまま運用すると該当受注が毎回再処理されること（ほかの未解決参照と同じ）。
- 案内文と Mappings タブの説明に「インポート前に設定する。未マッピングで取り込んだ受注は次の取込みで更新される」を追記（`2cbd4bd`）。
- テスト: `ImporterTest` に実 Writer の結合テスト（未設定で取込み→checksum なし→設定→dry-run が検証し直す→再取込みで `bacs`→checksum 保存）、`OrderWriterTest` 2 件、`WarningCodeTest` の旧テストを新しい挙動に書き換え。ミューテーション（2 コードをそれぞれ外す）で CAUGHT。
- この変更より前に取り込んで checksum が保存済みの受注は直らない（Tools のサンプル削除→再取込み）。v1.0 公開前なので実害は小さい。docs/03 §6・docs/10 R3-0m・`.claude/rules/sync-export-tools.md` に記録した。
