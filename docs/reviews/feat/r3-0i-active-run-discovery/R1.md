## 指摘
### [R1-1][High][src/tabs/ToolsTab.tsx（cleanupBlocked）]
クリーンアップの停止判定を「一覧を取得済みなら今の一覧だけ」にしたため、run の最中に取ったプレビュー（件数が過少、件数 0 なら `runCleanup()` は確認ダイアログを出さない）のまま、run の終了後に削除ボタンが有効になる（main からの退行）。逆に、一覧が空のまま取得済みでプレビューが `run_in_progress: true` を返しても止まらない。`SampleCleanup::run()` はプレビューと無関係に mapping 全件を削除する。（独立レビュー）
**修正方針:** `isCleanupBlocked()`（新設 `src/components/cleanup-gate.ts`）で「プレビュー時点の run・今の run・プレビュー後に見た run（`previewOutdated`）」のいずれでも止め、取り直しを求める案内を出す。プレビュー時に一覧も取り直す。

### [R1-2][Medium][src/tabs/ImportTab.tsx（retryJob）, src/hooks/useActiveRuns.ts]
Import の Retry の 409 の `active_runs` を、応答を待つ間に切り替えた別プラットフォームの一覧として取り込み、そのセクション・localStorage に別プラットフォームの run を入れうる（ExportTab・ToolsTab は世代でガード済み）。（独立レビュー）
**修正方針:** seed を「要求時のプラットフォーム」と組（`activeRunsSeed()`）にし、`useActiveRuns` が選択中と違う seed を捨てる（呼び出し側のガードに依存しない）。

### [R1-3][Medium][src/hooks/useRunAdoption.ts]
reconcile が一覧も取り直すため世代が進んで再び reconcile に入り、ポーリングが失敗し続ける（404 以外）間は一覧 GET を遅延なしで繰り返す。「一覧 1 つにつき 1 回」が上限として働かない。（独立レビュー）
**修正方針:** reconcile はポーリングの取り直しだけにする（一覧が古いだけなら、追跡中の run はボタンを止めないので害は無い）。

### [R1-9][Medium][テスト]
R1-1〜R1-3 の判定が hook・コンポーネントの中にあり Jest で固定されていない。（独立レビュー）
**修正方針:** `isCleanupBlocked()`・`runsToAnnounce()`・`activeRunsSeed()` を純粋関数に切り出してテストし、ミューテーションで固定を確認する。hook 内の照合（seed の破棄・reconcile の 1 回）はフックのテスト基盤（@testing-library/react）が無いため実機で確認し、テスト基盤の導入は backlog（R1-L1）。
