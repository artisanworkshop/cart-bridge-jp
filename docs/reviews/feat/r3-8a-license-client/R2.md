## 指摘
### [R2-1][Medium][plugins/cart-bridge-jp-pro/includes/Admin/LicensePage.php:handle_request()・tests/unit/Admin/LicensePageTest.php]
`handle_request()` の `exit` に届くと PHPUnit のプロセスごと終了コード 0 で終わる。`wp_safe_redirect()` を消す変異で、136 件中 116 件が走らないまま exit 0 になった（独立レビューの実測）。CI は終了コードしか見ないので、転送を外す退行で Pro の残りのテストが黙ってスキップされ、緑のままになる。
**修正方針:** 転送の後の `exit` をコンストラクタで差し替えられるようにし、テストは `exit` の代わりを渡す。`wp_redirect` フィルターは転送先を記録して空を返す（`header()` の前で止める）。
**対応:** 修正済み。転送を消す・終える処理を消す、の 2 種の変異が CAUGHT（PHPUnit は最後まで走る）。

### [R2-2][Low → 修正済み][plugins/cart-bridge-jp-pro/tests/unit/License/LicenseManagerTest.php:test_a_failed_activation_saves_nothing]
「有効化の失敗の理由を返す（突き合わせの理由ではない）」を、有効化と状態確認に同じ応答を積んでいたので確かめられていなかった。
**対応:** 状態確認の応答を別の文のフィクスチャにした。失敗の代わりに状態確認の結果を返す変異が CAUGHT。

### [R2-3][Low → docs に記録][plugins/cart-bridge-jp-pro/includes/License/LicenseManager.php:activate()]
未有効化でも、別のキーで試し直したとき（DB の複製を含む）は、別のキーの有効化を自分のものと読みうる。入力したキーにも期間内のリソースがあるので権利の迂回にならず、有効化数は無制限（D14）、無効化は instance で消すので害は無い。
**対応:** 許容し、docs/03 §10.7「R3-8a の実装」に前提を書いた。

### [R2-4][Low → backlog][plugins/cart-bridge-jp-pro/includes/License/LicenseManager.php:activate()]
販売サイトが応答しないと、未有効化のサイトでは有効化と突き合わせで待ちが最大約 30 秒になる（壁時計の制限が 30 秒のホストでは通知の出ない 502。何も保存しないので害は無い）。
**対応:** docs/03 に書き、backlog `r3-8a-license-client/R2-4` へ。
