## 指摘
### [R1-1][Medium][plugins/cart-bridge-jp-pro/includes/License/LicenseManager.php:activate()]
サーバーが有効化を記録したのに応答を受け取れない（タイムアウト・通信断・壊れた応答）と、ローカルは未有効化のまま以後の有効化が「同じ instance で有効化済み」で断られ続ける。未有効化の画面には有効化のフォームしか無く、無効化・状態確認もできない（instance は作り直さない設計）。独立レビュー。サーバーの `status()` が instance だけで有効化を見ることは `wc-am-api-requests.php` の `status()`（`is_instance_activated()`）で確認した。
**修正方針:** 未有効化のサイトで有効化が失敗したら、入力したキーで状態確認し、サーバーがこの instance を有効化済みと答えたら有効化として保存する（キーの交換では突き合わせない）。

### [R1-3][Medium（Low から格上げ）][plugins/cart-bridge-jp-pro/includes/License/LicenseStore.php:instance()]
instance を `wp_generate_password()` で作っていた。pluggable で `random_password` フィルターも掛かり、パスワードの規則を足すプラグイン（よくある）が記号を混ぜると `INSTANCE_PATTERN` に合わず、呼ぶたびに作り直す。有効化と無効化・状態確認で違う instance を送り、無効化は必ず失敗する。独立レビューは Low としたが、起こりうる条件で機能が壊れるので Medium とした。
**修正方針:** `bin2hex( random_bytes( 16 ) )` で作り、`random_password` を壊したテストで固定する。

### [R1-2][Low → 修正済み][plugins/cart-bridge-jp-pro/includes/Admin/LicensePage.php:failure_message()]
猶予期間の後（猶予期間 0 の販売サイトでは期限の直後）は状態確認が「No licensing resources exist」のエラーになり、「期限後もこのサイトで使い続けられる」の説明が出ない（`status_expired` の経路だけで出していた）。エラー時の表示なので R1 で直した（cbj-dev-cycle の例外）。
**修正方針:** 有効化済みのサイトで状態確認が SERVER_ERROR になったときも、条件付きの説明を添える。docs/03 に猶予期間 0 の振る舞い（ソースから・未実測）を書く。

### [R1-4][Low → 修正済み][plugins/cart-bridge-jp-pro/tests/unit/License/LicenseConfigTest.php]
1.0.0 の公開を止めるテストが実行時の定数を読んでいて、wp-config・`.wp-env.json` の `config` で定数を定義した環境では既定値が空でも通る。http の URL も通していた。数行で直せ、公開の止めなので直した。
**修正方針:** メインファイルの `define()` の既定値を読んで判定し、1.0.0 以上では https を要求する。

### [R1-5][Low → 修正済み][plugins/cart-bridge-jp-pro/includes/Admin/LicensePage.php:render_page()・failure_message()]
案内の文が、サーバーが断った理由を見ずに付き、「期限後」と言い切っていた（期間内でも、顧客が My Account で有効化を消した・複製したサイトが同じ instance で無効化した場合に「サーバーに載っていない」状態になる）。キーの交換の案内も、猶予期間中は無効化（ローカルの有効化も消える）より状態確認の方が安全なのに無効化だけを勧めていた。画面の表示なので R1 で直した。
**修正方針:** 案内を「もし〜なら」の形にし、未有効化のサイトの失敗には付けない。キーの交換は「期限内は先に無効化・期限後は先に状態確認」と案内する。

### [R1-6][Low → 修正済み][plugins/cart-bridge-jp-pro/includes/Admin/LicensePage.php:posted_key()]
`sanitize_text_field()` が `%XX` を取り除き、形の違う入力を別の（形の合う）キーに変えて送りうる。検証の方針（不正なら拒否）に合わない。1 行なので直した。
**修正方針:** `wp_unslash()` だけにして、`normalize_key()` の正規表現で拒否させる。

### [R1-7][Low → 修正済み][plugins/cart-bridge-jp-pro/tests/unit/Admin/LicensePageTest.php]
`handle_request()`（`current_action()` から操作名を取り出して処理し、設定画面へ戻す）と、未有効化のサイトに案内を付けないことのテストが無かった。
**修正方針:** `wp_redirect` フィルターで例外を投げて `do_action( 'admin_post_…' )` を通すテストと、案内が付かないことのテストを足す。
