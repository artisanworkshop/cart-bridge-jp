## 指摘
### [R1-1][Medium][includes/Woo/WarningCatalog.php: TERM_REUSED_EXISTING / TERM_NAME_CONFLICT]（独立 S-1）
detail 付きの文言が「under the same parent (ID %s)」で、親カテゴリーの ID と読める。実際は衝突・再利用したターム自身の ID で、対処（既存を改名・削除）と合わせると親を消させる誤読を招く。
**対応: 修正済み**（「with the same name (ID %s) under the same parent」）

### [R1-2][Medium][WarningCatalog.php: PRODUCT_PRICE_INVALID / VARIATION_PRICE_INVALID（エクスポート）]（独立 S-2）
税込への換算だけ失敗した場合も `ProductReader` は `*_PRICE_INVALID` を `PRICE_TAX_BASIS_UNRESOLVED` と一緒に積むが、文言は「定価が無い」「この商品はそのバリエーション抜きで送る」で、実際は商品ごと止まる。
**対応: 修正済み**（「価格が無効、または税込に換算できない」とし、換算できないときは商品ごと止まり税率を直すと案内。以前送ったバリエーションはプラットフォームに残る旨も追記）

### [R1-3][Medium][WarningCatalog.php: VARIATION_STOCK_MANAGEMENT_MIXED]（独立 S-3）
判定は全バリエーションが在庫管理外でも在庫状況（在庫あり／在庫切れ）が混ざれば真だが、原因の文が「管理するものとしないものが混在」だけで、blocking の原因が見つからない。
**対応: 修正済み**（在庫状況の混在も原因に書いた。対処は D22 の文言のまま）

### [R1-4][Medium][WarningCatalog.php: 税の対処（TAX_CLASS_MISSING・TAX_RATES_NOT_CONFIGURED・REDUCED_TAX_CLASS_NOT_FOUND・TAX_CLASS_UNSUPPORTED・VARIATION_TAX_CLASS_UNSUPPORTED・TAX_STATUS_NOT_TAXABLE・ORDER_LINE_TAX_CLASS_UNSUPPORTED）]（独立 S-4）
税計算 OFF の店舗では Tax タブも商品の税の欄も出ないのに、そこを案内している（`TAX_RATES_NOT_CONFIGURED` は税計算 OFF の新しい店舗で軽減税率の全商品に付く）。
**対応: 修正済み**（取込みは「税計算 OFF なら対処不要」、エクスポートは「税の設定と商品の税の欄は税計算を ON にすると出る」を追記）

### [R1-5][Medium][WarningCatalog.php: SALE_END_DATE_NOT_PUSHED]（独立 S-5）
セール終了後もプラットフォームがセール価格で売り続ける（金額）うえ対処も持つのに `info`（対処不要）。
**対応: 修正済み**（`action_required`）

### [R1-6][Medium][WarningCatalog.php: ORDER_LINE_VARIATION_UNMATCHED ほか受注の「手で直す」対処]（独立 S-6）
`order_line_variation_unmatched` は checksum を保存しないので取込みのたびに明細が作り直され、手で結んだ明細が外れる。同じ受注に再試行対象の警告が残る間は、数量・金額・合計の手修正も上書きされる。取込み側の `customer_account_protected` の「受注を手で割り当てる」も、ASP の受注が変わると戻る（独立 S-12 の一部）。
**対応: 修正済み**（「取込みを終えてから直す」「取り込み直すと書き直される」を追記）。挙動自体は R1-X1

### [R1-7][Medium][tests/unit/Admin/RestControllerTest.php: test_report_is_streamed_in_the_users_locale]（独立 S-7）
テストが後から足す優先度 10 の `locale` フィルターが `WP_Locale_Switcher::filter_locale()` を上書きし、切替の直後に戻す変異が NOT CAUGHT だった（CSV を切替中に書くことを固定していない）。切り替えなかったときに戻さないこと（`if ( $switched )`）も未テスト。
**対応: 修正済み**（`locale` フィルターを優先度 1 にし、`gettext` で文言が翻訳された時点の `determine_locale()` を記録して `en_US` を表明。外側で先に切り替えた言語を戻さないテストを追加。`mutate-check.sh` で「切替の直後に戻す」「ガードを外す」の 2 種が CAUGHT）

### [R1-8][Medium][WarningCatalog.php: TAX_CLASS_UNSUPPORTED / VARIATION_TAX_CLASS_UNSUPPORTED / ORDER_LINE_TAX_CLASS_UNSUPPORTED]（自己レビュー）
標準の税区分に JP 10% 以外を入れた店舗では detail が `Standard` になり、「税区分 “Standard” は標準税率（10%）でも軽減税率でもない」という矛盾した文になる。
**対応: 修正済み**（「JP の 10%（標準）・8%（軽減）の税率が無い」と書いた。0%・5% の JP の税率がある場合も税率が無い場合も正しい）

### [R1-9][Medium][tests/unit/Woo/WarningCatalogTest.php]（独立 S-8。テストの欠落なので Low から Medium に変更）
detail 付きの文言の `%` を `%%` にし忘れると `ValueError` で黙って detail の無い文言に倒れるが、固定するテストが無い（`(10%%)` → `(10%)` の変異が NOT CAUGHT）。
**対応: 修正済み**（`entry()` をリフレクションで呼び、全コード×向きの detail 付きの文言が書式として正しく detail を含むことを確かめるテストを追加。同じ変異が CAUGHT）

### [R1-10][Medium][WarningCatalog.php: CURRENCY_MISMATCH（取込み）]（独立 S-10。金額の誤読を招く文言なので Low から Medium に変更）
受注は店舗の通貨で円の数値のまま入る（¥1,000 が 1,000 USD）のに、「円の金額のまま取り込む」と円で記録されたように読める。
**対応: 修正済み**（例を添えて「店舗の通貨で、円の数値のまま」と書いた）

### [R1-11][Medium][WarningCatalog.php: 文言の事実誤り（ORDER_LINE_AMOUNT_INVALID〔取込み〕・PRODUCT_IMAGE_PUSH_INCOMPLETE／FAILED・COUPON_SAVE_FAILED・COUPON_CODE_CONFLICT・ORDER_DISCOUNT_NOT_PUSHED・ORDER_FEE_NOT_PUSHED）]（独立 S-11 前半・S-12。このタスクの成果物そのものの事実誤りで、R3-3 の FAQ に流用する前提なので Low から Medium に変更）
