## 指摘

### [R1-1][High][includes/Woo/Writer/TermWriter.php:58-65（修正前）]
`TermWriter::validate()` は `existing_local_id` が非nullなら常に `OPERATION_UPDATED` を返していたが、
`write()` の `update_existing()` は対象タームが手動削除等で既に存在しない場合（`wp_update_term()` が
`invalid_term` を返すケース）に新規作成へフォールバックし、他プラットフォーム由来の同名タームと
衝突すれば `TERM_NAME_CONFLICT` で見送る。`validate()` はこのフォールバックを一切再現しておらず、
実際には「新規作成される／衝突してskipされる」アイテムを dry-run が「更新される・警告なし」と
誤って報告する。CustomerWriter/OrderWriter/ProductWriter は同種のstale-ID対応を `write()`/`validate()`
共有の private メソッドで実装済みで、TermWriter だけがこの対称性を欠いていた。本PRの目的
（dry-runの警告が実移行の実態と一致すること=D14）そのものに反するドリフト。

**修正方針:** `plan()` で `get_term($existing_local_id, $taxonomy)` による読み取り専用の存在確認を行い、
`TermPlan::$existing_term_exists` として公開。`validate()` は既存タームが実在する場合のみ
`OPERATION_UPDATED` を返し、stale の場合は新規作成パス（`preresolved_conflict_term_id` による
衝突判定込み）へ合流させ、`write()` と同じ結果になるようにした。
