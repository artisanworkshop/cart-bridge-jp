### [Low][includes/Woo/Writer/OrderWriter.php:327 / includes/Woo/Support/MappingCandidates.php:130]

キーを無条件に受理する。REST を直接PUTすれば`status_map`に`checkout-draft`を保存でき、受注が
日次cronで完全削除される経路自体は残る（UI経路は塞がれたため実害の蓋然性は低い）。

### [Low][src/tabs/ExportTab.tsx:99-104 / includes/Admin/RestController.php:537-561]
R1-6「失敗時は空配列へ倒す」とR1-4「候補に無い値は`(no longer available)`表示」が重なると、
ASP側候補取得が一時的に失敗（レート制限・トークン期限切れ等）しただけで、カテゴリーマッピングの
既存の正常な値が全行「(no longer available)」と表示されうる（保存しなければデータ損失は無い）。

### [Low][src/tabs/ExportTab.tsx:89, 242-259]
R1-4はtarget側の孤立値のみを扱っており、source側の孤立エントリ（廃止されたASP決済方法・
削除されたWooカテゴリー等）は行自体が描画されないまま`edited`に残り、保存で再永続化される
（term ID/gateway IDは再利用されないため実害はほぼ無く、不可視のゴミデータに留まる）。

### [Low][src/tabs/ExportTab.tsx:339-344]

`can_create_category=true`のASPを追加した際に説明だけが残る。
