### [G3-1][Copilot][High][includes/Woo/Reader/ProductReader.php:98]
G2-3で追加した`ALL_VARIATIONS_EXCLUDED`警告は`ReadItem`に積むだけで、実際のpush自体を
止めない。`Exporter`はこの警告を見ずに`$writer->write()`を呼ぶため、`variants=[]`の
`CanonicalProduct`が通常のsimple商品としてpushされ、変換先（E2-3以降）でvariable商品の
構造（remote側の既存バリエーション）が失われうる。
判定: 修正（妥当。警告を積むだけでは実害を防げていなかった）
**対応:** `WarningCode::indicates_export_blocking()`を新設し、`Exporter::process_items()`が
これに該当する`ReadItem`を`$writer->write()`へ渡す前にskipped扱いでフェイルクローズする
（dry-runレポートには通常どおり反映される）。テスト
`test_export_blocking_warning_prevents_push`を追加。
コミット: 12c608a / スレッド: https://github.com/artisanworkshop/cart-bridge-jp/pull/40#discussion_r4001791004

### [G3-2][Codex][High（P1・部分対応）][includes/Woo/Reader/ProductReader.php:214]

canonical price契約は税込前提（`ProductWriter`のインポート方向と同じ契約）。無警告のまま
exportすると実際より低い価格がASP側に登録されうる。
判定: 一部修正（`ProductWriter`（インポート方向）も同じ制約を実際の税換算はせず警告のみで

CLAUDE.mdが要求する慎重な設計が必要な別スコープのため、警告追加のみをこのラウンドで
対応し、換算自体は`docs/review-backlog.md` `e2-2-exporter-core/G3-M-tax-basis-conversion`
へ送る）
**対応:** `ProductWriter`と同じ基準（1回だけ）で`PRICES_INCLUDE_TAX_DISABLED`警告を追加。
テスト`test_prices_excluding_tax_warns`を追加。
コミット: 12c608a / スレッド: https://github.com/artisanworkshop/cart-bridge-jp/pull/40#discussion_r4001792473

### [G3-4][Codex][High（P1）][includes/Sync/Exporter.php:246]
アダプタがupdate時に既存remote_idと異なる新しいremote_idを返す場合（例: リモート側で
削除された実体を再作成した）、`MappingRepository::upsert()`のユニークキー
（platform, entity_type, remote_id）は新remote_idで別行をINSERTするだけで、旧remote_idの
行が孤児として残る。`find_many_by_local_ids()`/`find_remote_id()`はid昇順の最初の行
（＝古い方）を採用するため、以後のエクスポートは永久に削除済みのremote_idへ再送し続け、
重複行が無料版の累計カウント（`LimitPolicy`）も押し上げる。
判定: 修正（妥当。アーキテクチャ原則7「無料版上限」に関わるHigh）
**対応:** `Exporter::process_items()`で新旧remote_idが異なる場合、upsert前に
`MappingRepository::delete_one()`で旧行を削除する。テスト
`test_stale_mapping_row_is_replaced_when_writer_returns_a_new_remote_id`を追加。
コミット: 12c608a / スレッド: https://github.com/artisanworkshop/cart-bridge-jp/pull/40#discussion_r4001792478

### [G3-6][Copilot][High（本文 Suppressed comments）][includes/Sync/ExportSampleSelector.php:118]

### [G3-5][Codex][High（P1・保留）][includes/Sync/Exporter.php:169]
`push_product()`が商品本体作成後に画像・バリエーション等の別リクエストを行う実装
（E2-3のスコープ）になった場合、後続リクエストの失敗・レート制限到達を「部分完了
（remote_idは確定・サブリソースは要再試行）」として表現する耐久的な契約が
`PushResult`/`Exporter`に無い。アダプタが例外を投げれば1件失敗として扱われるが
remote_idはどこにも記録されず再実行で重複作成される。remote_idを警告付きで返しても、
その警告が`indicates_unresolved_reference()`の対象外なら`Exporter`はchecksumを
キャッシュしてしまい、以後の再試行でアダプタ自体がスキップされ欠落が永久に修復されない。
判定: 保留（現状のColorMe `push_product()`は単一呼び出しで例外を投げるのみ
（複数リクエストへの分割はE2-3で初めて実装される）ため、この問題は今のコードベースでは
まだ発生し得ない。`PushResult`/`Exporter`への部分完了契約の追加は新しい設計判断であり、
E2-3の`push_product()`実装と併せて設計するのが適切）
**対応:** `docs/03-design-decisions.md` §10.2「E2-3/PR-Bへの申し送り」と
`docs/10-tasks.md`のE2-3行に必須対応として記録。`docs/review-backlog.md`
`e2-2-exporter-core/G3-H-partial-completion-contract`にも記録。
スレッド: https://github.com/artisanworkshop/cart-bridge-jp/pull/40#discussion_r4001792484（返信のみ、未Resolve）
