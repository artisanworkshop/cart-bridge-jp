## 新規指摘

### [R2-1][Low → 修正済み（検出できない限界を明記し、除外を可視化）][gate-record.sh:load_record]
`git merge-base --is-ancestor X X` は 0 なので、対象 HEAD が修正の commit そのもの・その子孫のとき（修正を push した後に `init`
した、記録を手で書き換えた）は、承認より前の commit も除外される（実測 rc=0）。正当な再指摘（前のラウンドの修正 commit が対象
HEAD そのもの）でも自分自身の除外は必要なので、コードでは区別できない。
**修正:** 除外した commit は `note:` として stderr に毎回出し、目で確かめられるようにした。SKILL.md・ヘッダの「限界」に、`init` を修正の前に
実行することと併せて明記した。テスト追加（note の出力・対象 HEAD 自身の除外が既知の限界であること）。

### [R2-2][Low → 修正済み][gate-record-parse.pl:138]
R1 で `auto-commit` の終端を `(?![A-Za-z0-9-])` に締めたが、固定するテストが無かった（緩める変異が NOT CAUGHT）。緩むと承認が auto 側に倒れて
時刻の検査を飛ばす方向。**修正:** `auto-commitX`・`auto-commit-x` を読めない値のループに追加（rc=1・「承認 must be」）。変異を検出。

### [R2-3][Low → 限界を注記][verify-rest.php:step 3]
`warned >= 印の数` は、ブロック以外の警告（商品データの品質など）と区別できない。今の環境では退行を検出できるが、データ品質の警告が
印の数以上ある環境では偽の PASS になりうる。**対応:** 限界としてコメントに明記した。印のある local_id ごとの厳密な確認は backlog へ。

### [R2-4][Low → 修正済み][.claude/rules/skill-scripts.md]
R1 で足した「限界」の例示 `out=$(f)` が不正確。`set -e` 下で単独の代入文なら本体が止まり完了マーカーが検出する（実測 rc=1）。
検出できないのは、終了コードを消費する形（`out=$(f) || RC=$?`・`if out=$(f)`。`run_gr` がこの形）だけ。**修正:** 例示を訂正した。
