## 指摘

### [独立-1][Medium][.claude/skills/cbj-dev-cycle/scripts/gate-record.sh:approve]（独立レビュー指摘）
`approve --force --auto-commit` を 1 回実行すると、承認より前の commit を挙げた記録（`check` が 1）が
`auto-commit` 扱いで合格（0）に変わる。「承認 is missing」のエラー文もこの経路を案内していた。
**修正:** 時刻承認の記録を `--auto-commit` で置き換えるのを拒否する（exit 2。`--force` でも不可。時刻承認に
戻すには `--force` を `--auto-commit` なしで実行し、commit し直す）。`auto-commit` の承認を書き直すのは可。
テスト追加（拒否・時刻承認が残る・`check` が引き続き 1・auto の書き直しは可）。

### [独立-2][Medium][gate-record.sh:load_record（順序検査）]（独立レビュー指摘）
判定「修正」の指摘が挙げた sha は承認より前のものがすべて違反になり、前のラウンドで直した指摘を bot が
再指摘したケース（判定は「修正済み」）を正しく記録できない。通すには保留と偽るか `auto-commit`・時刻の遡りしか無く、
独立-1 の抜け道へ誘導していた。
**修正:** 記録の「対象 HEAD」の祖先の commit は検査しない（`git merge-base --is-ancestor`）。対象 HEAD が無い・
存在しない・祖先でないときは除外せず検査する（フェイルクローズ）。テスト追加（祖先は 0・祖先でなければ 1・
対象 HEAD が存在しなければ 1）。ミューテーションで除外の削除・「常に除外」を検出することを確認した。

### [独立-3][Low → 修正済み][gate-record-parse.pl:承認時刻]（独立レビュー指摘）
承認時刻のパースが読めない値をフェイルオープンで受け入れる（全角数字→年 0 が 2000 に、`0000`→2000、`0126`→2026、
`0099`→1999〈`timegm` の世紀補正〉、末尾の `Zjunk`）。実測で確認。
**修正:** `[0-9]` のみ・年は 2000〜2099 だけ・末尾を `(?![A-Za-z0-9])` で固定。`timegm` は `eval` で受けて `bad` に倒す。
テスト追加（5 種）。

### [独立-4][Low → 修正済み][gate-record.sh:approve]（独立レビュー指摘）
`approve` の grep/awk が記録の構造（ヘッダ・コメント・コードフェンス）を見ず、パーサと書き手の解釈が食い違う
（検証欄のフェンス内の `- 承認:` で「already has」と拒否／`--force` で削除、コメント内の `- PR:` の中へ挿入）。
記録の PR 番号・ラウンドも照合していなかった。
**修正:** 位置と既存の承認の有無をパーサの JSON（`pr_line`・`approval_line`）から決め、PR・ラウンドを引数と照合する。
パーサはヘッダの承認・PR 行を構造行（コメント・フェンスの外）からだけ捕捉する。テスト追加。
