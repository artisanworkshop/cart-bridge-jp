## 指摘
### [R1-1][Medium][includes/Woo/Support/TaxClass.php:to_canonical]
標準でも軽減でもない税区分を Woo のスラッグのまま返すため、`reduced-rate` に 5% や他国の税率だけを入れた店舗では、正規化モデルの軽減税率の記号と同じ文字列になり、
アダプタの多重防御（`ProductTransformer::push_blocker()`）が素通りして `tax_reduced=true` の payload を作る（独立レビュー A-1。一時テストで実測）。本番は Reader の止める警告で止まるが、docblock が主張する多重防御が最も起きやすいスラッグで働かない。
**修正方針:** 標準・軽減以外は `TaxClass::UNSUPPORTED_PREFIX`（`woo:`）を付けたスラッグにする。→ **修正済み**（`3d6ac19`。`TaxClassTest::test_an_unsupported_class_never_collides_with_the_reduced_token`）

### [R1-2][Medium][includes/Woo/Support/TaxClass.php:classify]
標準の税区分 `''` は税率を見ずに常に標準としていたため、標準に JP 8%（食品だけの店舗）や 0% を入れた店舗の商品が標準税率（10%）として送られる（独立レビュー A-2。計画上の選択の再確認）。
**修正方針（2026-10-06 ユーザー決定「エクスポートだけ税率で分類」）:** `''` も JP の税率があれば税率で分類し（8% → 軽減、0% → 止める。detail は `Standard`）、JP の税率が無ければ標準のまま（新しい店舗・基準所在地が US の店舗で全商品を止めない）。
取込みの標準側（常に `''` へ入れる）は変えず backlog `R1-X1` に記録。→ **修正済み**（`3d6ac19`。`TaxClassTest` のデータセット 3 件・`ProductReaderTest::test_the_standard_class_follows_its_jp_rate`）

### [R1-3][Medium][includes/Woo/Reader/ProductReader.php:129・447 / OrderReader.php:309]
`get_tax_class()` の戻り値（フィルター `woocommerce_product_get_tax_class` などを通る外部由来の値）を `string` 型の引数へ渡すため、フィルターが null などを返すと strict_types 下で TypeError になり、
エクスポートのページ全体が落ちる（独立レビュー A-5 は Low としたが、以前の `in_array`・`'' !==` の比較では落ちなかった退行なので Medium に上げた）。
**修正方針:** `TaxClass::classify()`/`to_canonical()` と Reader の補助関数を `mixed` で受け、文字列でなければ `unconfigured`（止める）。→ **修正済み**（`3d6ac19`。`TaxClassTest::test_non_string_values_are_unconfigured`・`ProductReaderTest::test_a_non_string_tax_class_from_a_filter_blocks_without_crashing`）
