## 指摘
### [R1-1][Medium][plugins/cart-bridge-jp-pro/includes/License/LicenseClient.php:sections()]
API Manager は詳細の節のキーに**訳した**表示名を使う（`Licensing_Product_Tab::label()`。3.8.1 の `wc-am-api-requests.php` の `$sections[ $tab->label() ]`）。販売サイトが ja だと「説明」「変更履歴」などになり、
英語名の許可リストに当たらず節がすべて捨てられる（実測のフィクスチャは en_US の dev サイトだったので表に出なかった。同梱の ja の .mo を msgunfmt で確認）。
**修正方針:** WP の節の名前 => 英語と ja の表示名の対応表にする（`documentation` も足す）。ja の表示名のテストを足す。
**対応:** 修正済み（`SECTIONS` を対応表に、`section_key()`。`LicenseClientUpdateTest::test_information_reads_the_japanese_section_labels`）

### [R1-2][Low → 修正済み][plugins/cart-bridge-jp-pro/tests/unit/License/UpdateCheckerTest.php]
`test_wp_reads_the_update_through_the_header_host_filter` は docblock で「`wp_update_plugins()` の該当部分を通す」としながら `apply_filters` を 1 回呼ぶだけで、コアの変換（`(object)`・`new_version` の補完・`response`/`no_update` の振り分け・`id`）を通していない。
**対応:** `get_plugins()` のキャッシュに `Update URI` を差し込み、wordpress.org の応答（空）を先に積んで `wp_update_plugins()` を通すテスト 3 件（更新あり・最新・未有効化で販売サイトへ送らない）に置き換えた

### [R1-3][Low → 修正済み][plugins/cart-bridge-jp-pro/includes/License/LicenseManager.php]
有効化・無効化・キーの入れ直しの後も WP の更新の情報（`update_plugins`）が残る。無効化の後も前の確認の package（約 7 日有効）が次の確認（最大 12 時間）まで残って更新でき、有効化の直後は次の確認まで更新が出ない（画面の状態遷移）。
**対応:** 成功したときだけ `delete_site_transient( 'update_plugins' )`（`forget_update_info()`）。失敗では残す。`LicenseManagerTest` に 2 件

### [R1-4][Low → 修正済み][plugins/cart-bridge-jp-pro/includes/License/UpdateChecker.php:filter_update()]
期限内に自動更新を有効にしたサイトでは、期限後も package の無い更新を WP が新しい版ごとに試みて `no_package` で失敗し、失敗のメールを送る（`class-wp-automatic-updater.php`）。
**対応:** package が空のとき `disable_autoupdate => true`（`WP_Automatic_Updater::should_update()` が見る）。テストで固定

### [R1-5][Low → 修正済み][bin/build-zip.sh（Pro の名前空間の検査）]
小文字の宣言（PHP の名前空間は大文字小文字を区別しない）と、`<?php namespace …` のように行頭でない宣言を見落とす。宣言が 0 件（検査が壊れた兆候）でも通る（`.claude/rules/skill-scripts.md` のフェイルクローズ）。
**対応:** `grep -o -i` で宣言を 1 つずつ拾い、`CartBridgeJP\Pro`（とその下）でないものを止める。0 件は止める。小文字・同じ行・`Product`・大文字の `PRO` などを一時ファイルで確かめた

### [R1-7][Low → 修正済み][.github/workflows/release-pro.yml（と release.yml）]
タグ由来の `${{ steps.version.outputs.VERSION }}` を `run:` に直接埋め込んでいる（ref 名の `$(...)` がシェルに入りうる。タグを push できる人に限られる）。無料版の `release.yml` にも同じ形がある（横展開）。
**対応:** 両方とも `env: VERSION` で渡し `"$VERSION"` で参照する。actionlint green

### [R1-8][Low → 記録][UpdateChecker（マルチサイト）]

**対応:** マルチサイトは対象外として docs/03 §10.7「R3-8c の実装」の限界に書いた

### [R1-9][Low → 修正済み][plugins/cart-bridge-jp-pro/includes/License/UpdateChecker.php:render_update_message()]
