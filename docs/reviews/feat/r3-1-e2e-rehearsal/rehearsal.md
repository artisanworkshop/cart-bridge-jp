### 所見 A: 商品名の保存結果が「どのランナーで処理されたか」で変わる（リスク 9）

最初の取込みは `run.php` が管理者（unfiltered_html あり）として処理していたため、P12 の名前 `Tom & Jerry <set>` はそのまま保存された。
未ログインの HTTP リクエスト（WP-Cron と同じ条件）では WordPress の kses が有効で、`title_save_pre` が `Tom &amp; Jerry `（`<set>` が消え `&` が実体参照）にする（一時的な mu-plugin で実測）。
Action Scheduler の非同期ランナー（`WP_Async_Request`）は呼び出し元の Cookie を転送するため、管理画面を開いている間に処理されたページは管理者として、WP-Cron で処理されたページは未ログインとして保存される。
**同じデータでも取込みの結果が実行のされ方で変わる**。`run.php` に `context=cron|admin`（既定 cron）を足し、ローカルを初期化して cron の条件で取り込み直した結果、P12 は `ZZR-P12 name Tom &amp; Jerry ` で保存された（他の照合結果は同じ）。
プラグインは kses を外していない（`includes/` に `kses_remove_filters` 等の扱いが無い）。

### `option_market_price` の税基準（`docs/03` §10.2 の要検証）

管理画面のオプション一覧（項目・型番・在庫数・適正在庫数・販売価格・会員価格）にもストアフロントの「オプションの値段詳細」にも、バリエーションの定価は表示されない。
API には税込の対（`option_market_price_including_tax`）も無い。**表示からは税基準を判定できず、店舗・購入者に見える影響も無い**（販売価格は税抜換算 2,500 → 表示 2,750 円で正しい）。

## 所見 E: 日本語でインストールした WooCommerce では軽減税率の税区分が `reduced-rate` ではない（issue #102）

所見 D の対応方針（標準・軽減以外の税区分を止める）を検討する中で確認した。WooCommerce はインストール時に既定の税区分を翻訳された名前から作り
（`WC_Tax::create_tax_class( __( 'Reduced rate', 'woocommerce' ) )`、`class-wc-install.php` 1286 行）、日本語訳は「軽減税」「免税」
（言語パックで確認。確認後に削除）。スラッグは `sanitize_title()` で `%e8%bb%bd%e6%b8%9b%e7%a8%8e`・`%e5%85%8d%e7%a8%8e` になる。プラグインは軽減税率を
スラッグ `reduced-rate` 決め打ちで見分けるため、日本語でインストールした店舗では、取込みで軽減税率（8%）の商品が警告つきで標準税率（10%）の税区分になり、
エクスポートでは軽減税率の商品が非標準の税区分として hidden 安全策の対象になる。開発サイトは英語でインストールしたので `reduced-rate` があり、リハーサルでは表に出なかった。
R3-1d（issue #78）はこの方針を決めてから実装する。
