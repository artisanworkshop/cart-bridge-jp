## 指摘
### [R1-1][Low][plugins/cart-bridge-jp/includes/Core/Uninstaller.php:54・docs/03-design-decisions.md §7・tests/unit/Core/UninstallerTest.php:117]
AS のアクションを取り消す理由と、消さない設定のときの説明が実際の挙動と合っていない。停止時のフックが無いので、停止した時点から期限の来たアクションは
コールバックが無く AS が失敗にする。「消さないときは残す（再インストールで続きから動く）」は誤りで、取り消しが効くのは期限の来ていないもの（ログ整理の次回・遅延した再試行）だけ。
**修正方針:** 3 か所の文言を実態に合わせる。停止中に止まるジョブの問題は差分の外の既存の挙動なので対象外（R1-X1）として backlog へ。→ **Low → 修正済み**

### [R1-2][Low][plugins/cart-bridge-jp/tests/unit/Core/UninstallerTest.php:141]
グループ名の一致テストの `as_has_scheduled_action( LogCleanup::ACTION_HOOK, [], group )` は、tests サイトと共有の DB にブートストラップが予定したログ整理がコミット済みで
残っているため、`schedule()` が何もしないまま通る（`LogCleanup` のグループを変える変異をローカルで検出できない）。
**修正方針:** テストの中で先にそのフックを取り消してから（テストの終わりに戻る）`schedule()` する。→ **Low → 修正済み**（`LogCleanup` のグループを変える変異が CAUGHT になったことを mutate-check.sh で確認）

### [R1-3][Low][plugins/cart-bridge-jp/includes/Admin/RestController.php:check_uninstall_settings_permission・readme.txt]
マルチサイトでは、ネットワーク管理画面からの削除がメインサイトの文脈で動くので、設定はメインサイトの値だけが読まれる。サブサイトでもスーパー管理者は `can_change: true` でオンにできるが効かない（安全側）。
**修正方針:** readme の FAQ と docs/03 §7 に「マルチサイトではメインサイトの設定とデータだけ」と明記。画面の出し分けは単一サイトのテストで固定できない分岐が要るため見送り、backlog へ。→ **Low → readme・docs を修正、画面は backlog**

### [R1-4][Low][plugins/cart-bridge-jp/src/components/UninstallSettings.tsx:101-108]
真偽値の読み方が混在（警告は `true ===`、`checked`・`disabled`・説明文は truthy）。`.claude/rules/frontend.md`「REST の値は… 真偽値は `true` だけを真」と食い違う（サーバーは bool しか返さないので実害なし）。
**修正方針:** `checked={ true === … }`、`disabled={ true !== settings?.can_change || saving }`、説明文は `false === settings?.can_change`。→ **Low → 修正済み**（画面の状態に関わる Low。cbj-dev-cycle の例外）

### [R1-5][Low][plugins/cart-bridge-jp/languages/cart-bridge-jp-ja.po]

### [R1-6][Low][plugins/cart-bridge-jp/src/components/UninstallSettings.tsx:93・readme.txt・Uninstaller.php:55]
