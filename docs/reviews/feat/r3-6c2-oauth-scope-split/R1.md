## 確認したが問題が無かった点（独立レビューの実測を含む）
- `TokenStore` の書込み経路: トークンを書く本番の経路は `save_token_if_credentials_match()` だけで、同じ CAS の中で毎回 `scopes` を書く。`save_settings()`・`update_extras_if_token_matches()` は payload を引き継ぎ `scopes` を消さない。新しいコードで「記録なし」のトークンができるのは `TokenStore::save()`（テストとスキルだけ）
- `LEGACY_SCOPES` の前提: git の履歴で `SCOPE` 定数は F1-2 から 5 つのまま変わっていない
- スコープの過不足（swagger の security）: 無料版が叩くエンドポイント（products・variants・options・images・categories・groups・shop・stocks）は商品の 2 つかスコープ不要。`read_sales` が要る `GET /reviews` は ColorMe の `has_reviews=false` で呼ばれない。Pro の 3 つで customers・sales・shop_coupons を満たし、payments・deliveries はスコープ不要。クーポンは読取専用なので `write_shop_coupons` は要らない
- 信頼境界: フィルター（例外・配列でない → 商品の 2 つ、未知の値は除外、商品の 2 つは外せない）、応答の `scope`（無い・null → 要求したもの、文字列以外・空 → `[]`）、保存値（リストでない・文字列でない要素 → `[]`）。読めない値が「全部ある」に化けるのはキーが無いときだけで、新しいコードはその状態を作らない
- Pro の判定が null のとき: 種類の `supports_*` は false、マッピングの種類は `applies` が false で候補も取得しない、`entity_options` は try の中。Mappings の PUT は送られたキーだけを更新し、登録の無い種類の値も残す
- `GET /connections` は `manage_woocommerce` で保護。値は `KNOWN_SCOPES` のスコープ名だけ。フィルターの例外は `scopes()` が握る（テストあり）
- 画面: `missingScopes()` は `connected === true`・自前のプロパティ・空でない文字列だけを重複なく読む。`joinList()` を使い、Pro・種類の名前を出さない。警告の「Reconnect to %2$s」はボタンの表示と訳（「%sに接続し直す」）に一致
- `CBJP_EXTENSION_API_VERSION` 1→2 と Pro の要求 2、docs/03 の API の一覧。`FreeScopeTest`・`bin/build-zip.sh` の Pro の識別子のパターンに新しいコードは当たらない
