## 指摘

### [R1-1][Medium][includes/Woo/Support/ProductResolver.php:144]（独立レビュー A-1）
エクスポートで作った可変商品のバリエーションは取込みの印（`_cbjp_platform`）を持たない。D25 以前は商品の取込みが `VariationWriter` 経由で印を付けていたが、
D25 で取込みが止まったため付かなくなり、その商品を含む ColorMe 受注を取り込むと明細のバリエーション解決（`resolve_variation_by_options()` の所有判定）で全部除外され、
`ORDER_LINE_VARIATION_UNMATCHED` の商品リンクの無い行になる（単純商品は remote_id の mapping で解決できるので食い違う）。独立レビューがその場限りのテストで再現。
**修正方針:** 所有の印に加えて、このプラットフォームの variant の mapping で結ばれたバリエーションも対象にする（`find_many_by_local_ids()` で 1 クエリ）。

### [R1-2][Medium][tests/unit/Woo/Reader/StockReaderTest.php]（独立レビュー A-2。重大度を Low → Medium〔テスト欠落〕）
在庫行を作る箇所のうち、親に mapping の無い variable 商品のバリエーションの未解決行（`StockReader.php:164`）がテストで固定されておらず、引数を `false` にする変異が NOT CAUGHT。
docs の「在庫行 3 か所すべて CAUGHT」も実際の呼出し箇所（5 つ）と合っていなかった。
**修正方針:** 既存の一致テストに mapping の無い variable 親を足し、5 か所すべてをミューテーションで確かめて docs を直す。

### [R1-3][Medium][includes/Sync/ExportSampleSelector.php:66-89, 213-232]（独立レビュー A-3。重大度を Low → Medium〔性能・走査の正しさ〕）
受注の走査を ID 取得から実体取得（1 ページ 50 件の `WC_Order`＋`$keep` 内の `wc_get_order()`）に変えていた。読めない受注をデータストアが落とすと `count < SCAN_BATCH` で
次のページがあるのに打ち切られうる。`orderby => date` に決め手が無く、OFFSET ページングで同じ日時の行が重複・欠落しうる（`collect_newest()` も重複を除かない）。
**修正方針:** `'return' => 'ids'` に戻し（型定義は実体の配列なので、要素は正の整数として読める値だけを ID として扱う）、`orderby => 'date ID'`（顧客は `registered ID`）、
`collect_newest()` で重複を除く。

### [R1-4][Medium][.claude/skills/rehearse-colorme/php/check-import.php]（独立レビュー A-4。重大度を Low → Medium〔skill-scripts のフェイルクローズ〕）
`LINKED_BY_EXPORT` を常に成功として数えていたため、取込みだけの段階（手順 1）で「writer が既存の実体を結んだのに `_cbjp_platform` を書かない」退行（sync-export-tools ルールが
警告する危険）を `MISSING`（終了コード 1）ではなく成功として通してしまう。
**修正方針:** 既定では失敗に数え、作成エクスポートの後に `expect-export-links=yes` を付けたときだけ許す。

### [R1-5][Medium][.claude/skills/rehearse-colorme/php/seed-woo.php]（独立レビュー A-5。重大度を Low → Medium〔同上〕）
同じ名前・メールの実体が取込み品（前回の `ZZW-` を取り込んだもの）でも「skip」と出して続行し、手順 3 が取込み品を Woo 生まれとみなしたまま黙って成立しなくなる。
