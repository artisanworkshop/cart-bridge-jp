## 指摘
### [R1-1][High][includes/Support/PlatformLock.php:90,116]
「期限が `$now + TTL_LONG` より先なら壊れた値として回収する」判定に余裕が無く、判定する側の `time()` が保持する側より 1 秒でも遅れる（INSERT の前に読んだ時刻が秒境界をまたぐ・Web ノード間の時計のずれ）と、
取得したばかりの `TTL_LONG` のロック（クリーンアップ・push intent の解除のバッチ中）を CAS で奪い、2 者が同時に保持する（サブエージェントが `php -r` で now_B=1000・now_A=1001 を再現。`TTL_SHORT` では起きない）。
**修正方針:** 上限に時計のずれの余裕（`CLOCK_SKEW_SECONDS = 300`）を足す。`time() + TTL_LONG + 1` の行を保持中とみなすテストを追加。

### [R1-2][Low → 修正済み][includes/Sync/JobManager.php:150-159]
`start_run()` の先頭の `pending→running` が失敗した（キャンセルがジョブの作成の途中に届いた・UPDATE の DB エラー）とき、エンキューしないだけで後に作ったジョブが pending のまま残り、進まない run がプラットフォームを塞ぐ。
状態遷移・非同期の競合に関わり数行で直せるため R1 で修正（cbj-dev-cycle の例外）。
**修正方針:** 遷移が false なら `cancel_run( $run_id )` で run の残りも止める。2 件目のジョブの INSERT 直前にキャンセルを差し込むテストを追加。

### [R1-3][Low → 修正済み][tests/unit/Admin/RestControllerLockTest.php:180-187]
ロック保持中のテストが 409 しか確かめておらず、「ツールをロックの外（前）で実行して結果だけをコールバックで返す」形に壊しても全部通る（副作用を見ていたのは export options だけ）。
**修正方針:** 要求ごとに状態を変えたら観測できる前提を作り、409 の後に変わっていないことを確かめる（`untouched_probe()`。start・retry・クリーンアップ・再構築・export options・push intent）。

### [R1-4][Low → 修正済み][docs/03-design-decisions.md §5・includes/Sync/JobRepository.php:180]
「AS は既定 5 分を超えた in-progress を失敗扱い」の前提（キューランナーが動いたとき・`10 × queue_runner_time_limit`・`action_scheduler_failure_period`）と、そこから来る制限
（キャンセル後にワーカーが強制終了されると 409 が 5 分以上続く／1 ページがその時間を超えると判定から外れる）が書かれていない。
**修正方針:** docs/03 と docblock に前提と残る制限を明記。

### [R1-5][Low → 修正済み][docs/03-design-decisions.md §5 冒頭・.claude/rules/sync-export-tools.md]
docs/03 §5 の「同時実行: 同一 platform で running のジョブがある場合は新規開始を拒否」、rules の「`start_run()` は `has_active_job_for_platform()` で」が実装と食い違う。
**修正方針:** 現行（pending/running/paused＋処理中のアクション＋ロック、`is_platform_busy()`）に合わせる。
