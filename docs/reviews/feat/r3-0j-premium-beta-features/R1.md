## 指摘

### [R1-1][Medium][includes/Adapters/Capabilities.php・PlatformAdapter.php（契約）／ColorMeAdapter.php:149／ExportTab.tsx／Exporter.php:checksum_salt]（独立レビュー I-1）
「画像アップロード設定に従って送る」義務は `ColorMeAdapter` の実装だけにあり、`PlatformAdapter`/`Capabilities` のどこにも契約として書かれていない。一方 UI・REST・`Exporter` の印は「`can_push_images` が true の全アダプタ」を対象に汎用で動く。
`can_push_images=true` の外部アダプタ（Pro アドオン・将来の BASE/MakeShop）が設定を読まないと、Export タブには「既定オフ」の項目が出るのに画像は送られ、切替のたびに商品が再送されるだけになる。
**裏取り:** `grep` で `PlatformAdapter`/`AbstractPlatformAdapter`/docs/03 に外部アダプタへの義務の記述が無いことを確認。`MockPlatformAdapter` の既定は `can_push_images=true` で設定を読まない（テスト用のため実害なし）。
**対応: 修正済み** — 契約として明文化（`Capabilities` の docblock・`PlatformAdapter::push_product()` の docblock・docs/03 D24 実装 6.・`.claude/rules/adapters-colorme.md`）。ベータでないアダプタでも設定側の既定オフ（`ExportOptions`）で成り立つ。UI の分岐を `beta_features` に依存させる案は、汎用設定の設計と合わないため採らなかった。

### [R1-2][Medium][src/tabs/ExportTab.tsx:pushImagesHelp／docs/03 D24]（独立レビュー I-2）
画像をオンにすると export 済みの商品が更新として再送され、`push_images()` は既存画像を確認せず position 0〜 に POST する。ColorMe の `POST /v1/products/{id}/images` は「同じ position に画像が既に存在する場合は上書きされます」（swagger）ため、オフの間に案内どおり管理画面で手作業登録した画像が、予告なく Woo の画像で置き換わる（リモート側データの上書き）。UI にも docs にも警告が無かった。
**裏取り:** `tests/fixtures/colorme/swagger.json` の該当 `post.description` を読んで確認（上書きの記述あり）。`ColorMeAdapter::push_images()` は既存確認をしない。なお上書き自体は D24 以前から（プレミアムでは常時画像を送っていた）の挙動で、今回は「オンにする前に知らせる」ことが必要になった。
**対応: 修正済み** — 説明文に「同じ位置に登録済みの画像は WooCommerce の画像で上書きされる」を追記。docs/03 D24 実装 6.・`.claude/rules/adapters-colorme.md` にも記載。

## 確認したが問題なしの観点（独立レビュー＋自己レビュー）
1. `ExportOptions::push_images_enabled()` のフェイルクローズ（`'true'`・`1`・配列・`stdClass`・option 自体が非配列 → オフ。壊れた値からの保存復帰・autoload なし）

3. `platform` の取り方と権限（`get_url_params()`、`manage_woocommerce`、不明 platform は 404 でオプションを作らない）
4. 検証の順序（能力の無い platform はオン不可・オフ可、進行中〔pending/running/paused〕の run は 409）
5. checksum の印: skip 判定と upsert の両方に同じ値、他に export checksum を書く経路は無い（`PushIntentResolver`/`MappingRebuilder` は null）、dry-run も同じ判定、`Importer` の生ハッシュとは名前空間で分離、`LimitPolicy` は作成時のみ消費（更新の再送は影響なし）、`canonical_json()` が `{` で始まり印との境界が曖昧にならない、実行中に設定が変わっても次の run で自己修復
6. ColorMe の判定の一致（`should_push_images()` ＝ 設定 かつ プレミアム ＝ 印の条件）。キーは `self::ID` と `$adapter->id()` で同じ `colorme`
7. `Capabilities` の新引数の位置と正規化、`get_connections` の結合テスト
8. サーバー側で受注が暗黙に選ばれない（`POST /runs` は `entities` の明示が必須）
9. フロントの世代カウンタ（`platformGenerationRef` を進めるのはマッピング取得 effect だけ。新しい effect は宣言順で読む世代が正しい。`setPushImages` の `finally` は同世代のときだけ解除。取得失敗の Notice は破棄不可で「詰み」なし）
10. テストの質（ガード除去で落ちる形。オプションの後始末。ランダム順でも通る）。ミューテーション 15 件すべて CAUGHT（自己実施）
11. `PRODUCT_IMAGE_PUSH_INCOMPLETE` は `indicates_unresolved_reference()` に含まれ、印つきでも画像の一時失敗は checksum を保存せず再試行される
12. mu-plugin テンプレート（`is_array( $seed ) && is_array( $seed['capabilities'] ?? null )` の二段階で fatal なし。`php -l` OK）
