### [R2-1][Low][.claude/skills/measure-api-manager/php/status.php:17・php/teardown.php:27]
DB と結び付かない状態ファイル（DB を作り直した後に残ったもの）でも、teardown の入口と最後の数え直し（`status`）が、その状態ファイルの ID・承認のモードで数えていた。新しい DB でその ID が別の投稿・注文を指すと残りが 0 にならず、teardown が止まり続け、無関係な投稿を手で消す方向へ誘導する（自己検証で見つけ、サブエージェントも同じ指摘）。
**修正:** 結び付かないときは `cbjp_am_leftovers( null )`（名前と目印だけ）で数える。正常な teardown では、トークンを消す直前に `step=am` が状態ファイルの ID まで含めて 0 を確かめているので、守りは落ちない。
