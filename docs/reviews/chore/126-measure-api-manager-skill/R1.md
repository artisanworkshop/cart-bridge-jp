## 指摘

### [R1-1][Medium][.claude/skills/measure-api-manager/php/teardown.php:72]
属性の索引の更新の予定を消す処理が「製品がこのスキルの製品か」の判定で守られていない（別物の製品でも、索引の行が 0 ならその製品 ID の予定をログごと消す）。また状態ファイル（`dist/`。`wp-env clean`・`destroy` の後も残る）が dev サイトの DB に結び付いておらず、DB を作り直した後の teardown が、preflight が確かめていない DB で Pro のキーの記録・API Manager の名前のパターン・承認のモードを消し、状態ファイルの ID が別の投稿を指しうる（独立レビュー A1）。
**修正方針:** setup の init で乱数のトークンを option と状態ファイルの両方に書き、setup の続き・measure・e2e・compare・teardown は一致したときだけ動く（一致しない・無いときは、残りが無ければ何もせず、あれば止まる）。予定は「このスキルの製品を消した／その ID の投稿が無い」ときだけ消す。

### [R1-2][Medium][.claude/skills/measure-api-manager/php/e2e.php:54]
`wp_update_plugins()` は wordpress.org への要求が失敗すると `update_plugins_{host}` の前に戻り、transient は `last_checked` だけになる（`wp-includes/update.php`。`checked` はその後で入る）。`e2e check` の「in: none・要求 0 件」が「未有効化では問い合わせない」の期待と区別できず、コンテナが外に出られないときも合格に見える。`e2e activate` は失敗しても exit 0（独立レビュー A2）。
**修正方針:** `checked` に Pro が無ければ「WP が Update URI の段まで進まなかった」として exit 1。activate は `LicenseResult::is_success()` で終了コードを決める。

### [R1-3][Medium][.claude/skills/measure-api-manager/php/test-anon.php]
scheme の無い `localhost:10010`（measure が毎回 `object` に送る値）は匿名化で置き換わらず、漏れの検出の `host:port` の分岐だけが守りなのに、その分岐を確かめるテストが無い（独立レビュー A3。スクラッチパッドに写した anon.php でこの分岐を削っても全件合格）。
**修正方針:** `['object' => 'localhost:10010']` が漏れとして報告されることを確かめるケースを足し、分岐を壊す変異で落ちることを確かめる。
