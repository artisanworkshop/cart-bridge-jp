## 指摘
### [G2-1][Codex P1][.claude/skills/cbj-dev-cycle/scripts/gate-turn.sh:78]
`--first` は T を CI 待ちより前に取る。`bot-wait.sh` は提出時刻（`submitted_at > T`）だけで応答を判定し、commit_id を見ない。CI 待ちの間に PR の HEAD が動く（`ci-wait.sh` が明示的に扱っているケース）と、旧 HEAD への自動レビューが待ちを満たし、CI で green を確認した新 HEAD が未レビューのまま「応答あり」と報告される。
判定: **修正**。実コードで確認: `bot-wait.sh` は commit_id を参照せず、`ci-wait.sh` は HEAD の移動（`PR head moved … while watching`、push 直後の追従）を扱う。この repo の Codex は PR を開いた時にだけ自動レビューし、push では起動しないため、移動後の HEAD への自動レビューは来ない。
**対応:** `--first`（CI 待ちあり）のとき PR の HEAD を **T より先に**読み（逆順だと T と HEAD0 の間の push を検出できない）、CI 待ちの後にもう一度読んで比べる。動いていたら応答待ち・指摘の取得をせず exit 2 で終了し、`--first` を外して再実行する手順（新 HEAD への `@codex review`、届いていた自動レビューは依頼 1 回目として数える）を案内する。HEAD の取得失敗・空の値は exit 3（「動いていない」に倒さない）。`--no-ci-wait` と通常ターンでは HEAD を読まない。
**残る限界:** レビューの commit_id は照合しないため、PR 作成後に別のコミットを push してから `--first` を起動した場合は旧 HEAD への自動レビューと区別できない。ヘッダと SKILL.md に明記（その場合は通常ターン）。commit_id 照合まで入れなかった理由: Codex は「指摘なし」を issue コメント（`Reviewed commit:` の短縮 sha を含む本文）で返し、review オブジェクトが無いため、`bot-wait.sh` の判定全体を作り直すことになる。
コミット: a3e2399（修正）/ 7c492ba（限界の明記）
スレッド: [r4098175911](https://github.com/artisanworkshop/cart-bridge-jp/pull/66#discussion_r4098175911)

### [G2-2][Copilot][.claude/skills/cbj-dev-cycle/scripts/gate-turn.sh:53]
`TIMEOUT`/`CI_TIMEOUT` は `^[0-9]+$` の検証だけで、後続の `$(( ))` と子スクリプトは先頭 0 の値を 8 進数として解釈する（`--ci-timeout=0600` は 384 秒、`--timeout=0900` は見積り計算でエラー終了）。
判定: **修正**。bash 3.2 で実測: `$((0600))`=384、`$((0900))`=`value too great for base`、`$((10#0900))`=900。
**対応:** 検証を通った後に `TIMEOUT=$((10#$TIMEOUT))` / `CI_TIMEOUT=$((10#$CI_TIMEOUT))` で基数 10 に正規化してから、見積りと子スクリプトへ渡す。
**横展開（同一ファイル内）:** `PR` は `^[0-9]+$` を通るが算術には使わず文字列としてのみ使うため対象外。`bot-wait.sh`・`ci-wait.sh` を**直接**呼ぶ場合の先頭 0 は同種の問題を持つが、本 PR の対象ファイル外で、SKILL.md の例は先頭 0 なしのため `docs/review-backlog.md` に Low として記録（`gate-turn.sh` 経由なら正規化済みの値が渡るので影響なし）。
