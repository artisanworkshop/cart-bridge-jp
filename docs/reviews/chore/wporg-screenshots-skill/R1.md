## 指摘
### [R1-1][High][.claude/skills/wporg-screenshots/php/setup.php]（独立レビュー A-1）
claim したアクションを job_id で見分けず全部処理し、処理できるアクションが 0 件になった時点でループを抜けていた。`.claude/rules/skill-scripts.md` の規約（job_id を照合し、他の run は開いていれば手放し閉じていれば処理する）の半分しか実装しておらず、レート制限で paused になったジョブ（再開は 60 秒後の予定）を待たずに完了確認で失敗する。
**修正方針:** `rehearse-colorme` の `run.php` と同じ形（job_id の照合・他の run の扱い・paused の再開待ち〔最大 5 分〕・アクションを失ったジョブの検知）にする。→ **修正済み**

### [R1-2][Medium][.claude/skills/wporg-screenshots/scripts/capture.sh]（独立レビュー A-2）
後片付けがフェイルクローズでなかった。EXIT トラップの中でも `set -e` が効くので、先に実行する `rm -rf "$TMP"` が失敗すると mu-plugin の削除が走らない。`remove_mu … || rc=1` の形では関数の中で `set -e` が効かず、`rm` が失敗しても `removed` と表示して 0 を返していた（bash 3.2 で実測）。
**修正方針:** `remove_mu` は `rm` の失敗と削除後の残りを明示的に返す。`finish` は mu-plugin を先に消し、失敗は rc に残して残りの片付けを続ける。→ **修正済み**（`chflags uchg` で消せないファイルにして、`cleanup` と `remove_mu … || rc=1` の両方が 1 を返すことを実測）

### [R1-3][Medium][.claude/skills/wporg-screenshots/SKILL.md・php/setup.php]（独立レビュー A-3）
「tests サイトの DB は次の PHPUnit の起動で作り直される」は誤り。PHPUnit は tests サイトと同じ DB・接頭辞を使い、起動時に戻すのはコアのテーブルだけ。PHPUnit の後も撮影の dry-run のジョブ 42 件が残っていた（実測。サイト名だけは初期値に戻っていた）。
**修正方針:** 残るもの・戻るものを正しく書き、開いた run の扱い（R1-4）とあわせて説明する。→ **修正済み**

### [R1-4][Medium][.claude/skills/wporg-screenshots/php/setup.php]（独立レビュー A-4）
dry-run が途中で失敗すると `colorme` の run が開いたまま残り、次の撮影の `POST /runs` が 409 になる。PHPUnit も同じ DB を使うので、`colorme` で run の排他を通るテストが影響を受けうる。
**修正方針:** ガードを通った後・書き込みの前に、開いている `colorme` の run を `POST /runs/{id}/cancel` で閉じる。自分の run を始めた後に止まるときは、その run をキャンセルしてから終わる。→ **修正済み**（開いた run をわざと作って撮影し、`cancelled the open run …` の後に撮影が通り、その run のジョブが cancelled・残ったアクションが片付くことを実測）
